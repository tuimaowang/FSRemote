## Context

FSRemote 当前由 `DeviceGrid::refreshDeviceStatuses()` 并发连接每台目标的 TCP 49101，读取在线、被控人数、控制端名称和脚本运行信息。该模型在默认 60 秒周期下状态延迟明显，缩短周期又会产生设备数平方级的连接、超时和线程开销。远控会话的权威状态位于原生流主机，脚本权威状态位于目标设备本机 `work/fsremote_active_script.json` 和对应 PowerShell 进程，UI 不应通过本地旧缓存推断这些事实。

所有节点运行相同程序，并可能同时充当控制端和被控端。运行环境以 Windows 局域网为主，已有 Qt Network、设备 IP/MAC 信息、OpenSSH 公钥身份以及 TCP 49100/49101/49102/49103 和音频 49105；UDP 49104 可用于新的状态总线。实际部署同时存在 `192.168.1.0/24`、`192.168.2.0/24`、`192.168.3.0/24` 等可通过网关互通但广播域彼此隔离的网段，单纯向本机定向广播地址发送无法覆盖其它网段。用户要求不依赖旧版本周期轮询，状态变化需要实时反映，同时程序崩溃、断电和 UDP 丢包后必须自动恢复一致。

## Goals / Non-Goals

**Goals:**

- 使用一份对称的完整设备状态快照统一在线、被控会话、脚本运行和本机控制目标。
- 状态变化立即广播，空闲时低频心跳，活跃时高频心跳，并通过 TTL 自动判定离线。
- 通过本地消息队列和单线程状态归并器隔离网络线程、远控回调、脚本检测和 UI。
- 使用稳定设备 ID、启动 ID、会话 ID 和单调序号抵抗重复、乱序、延迟和设备重启。
- 被控人数只从目标设备公布的活动会话快照计算，脚本状态只从目标本机验证结果计算。
- 删除自动全设备 TCP 轮询；保留手动刷新进行一次显式 TCP 校准。
- 在可路由的私有 IPv4 网段之间使用 UDP 订阅租约和定向状态推送，使跨广播域设备仍保持事件驱动状态。

**Non-Goals:**

- 不让 UDP 广播承载关机、重启、脚本执行或远控输入等控制命令。
- 不保证跨互联网、NAT 或禁止 UDP 49104 转发的网络传播；同广播域使用定向广播，可路由私有网段使用已配置目标发起的 UDP 订阅。
- 不在首版实现中心服务器、RabbitMQ、Redis 或外部消息代理。
- 不使用增量式“人数加一/减一”协议，也不通过控制端租约直接推导被控人数。
- 不为旧版本设备提供实时广播兼容层。

## Decisions

### 1. 每台设备广播一份统一完整快照

新增 `DeviceRealtimeStateService`，绑定 UDP 49104，并向每个有效网卡的定向广播地址发送 JSON 快照。快照包含协议版本、设备 ID、启动 ID、序号、设备名/IP、被控会话列表、脚本三态状态和本机正在控制的目标列表。

选择完整快照而不是增量事件，是因为 UDP 丢失一次结束事件时，下一次快照仍能纠正状态。控制端和被控端不使用两种互相相加的协议，而是在同一对称快照中分别公布自身事实。

### 2. 使用身份、启动和序号三层去重

- `deviceId` 使用本机 OpenSSH 公钥文本的 SHA-256 指纹，跨程序重启保持稳定。
- `bootId` 在进程启动时生成 UUID；收到相同 `deviceId` 的新 `bootId` 时立即清空旧状态。
- `sequence` 在每次发送时单调递增；相同 `bootId` 下只接受更大的序号。
- `sessionId` 使用远控主机现有会话 ID；同一控制设备的新会话替换旧会话，不重复计数。

广播只影响只读展示状态，不承载敏感操作。首版接收端要求来源 IP 与设备快照公布 IP 一致，并只把已存在于设备列表中的 IP 映射到 UI。加密签名广播不在首版范围内，因为每秒调用外部 SSH 签名进程会显著增加开销。

### 3. 事件驱动广播配合自适应心跳

状态发生变化时，服务立即排队发送完整快照，并在约 100ms 和 300ms 后补发。重复变化在发送队列中合并，只保留最新快照。

- 存在远控会话、脚本运行或本机控制目标时，每 1 秒发送心跳快照，接收 TTL 为 5 秒。
- 完全空闲时，每 5 秒发送心跳快照，接收 TTL 为 15 秒。
- 心跳间隔加入小幅随机抖动，避免多台设备同时启动后同步发送。

心跳用于发现无法发送结束事件的崩溃、断电和网络中断；业务变化仍通过立即广播实现低延迟。

### 4. 单一消息队列和状态归并器

`DeviceRealtimeStateService` 在 Qt 主线程拥有 `QQueue<DeviceStateEvent>`。UDP `readyRead`、本地会话快照、脚本检测、控制目标变化和 TTL 定时器只负责产生规范化事件；队列通过单次排队调用批量排空，状态表只在一个线程修改。

服务发出最终的 `deviceStateChanged(ip, state)` 和 `deviceExpired(ip)` 信号。`DeviceGrid` 只消费最终状态，不再让后台网络线程直接写入三个状态缓存。

选择 Qt 排队信号和有界 `QQueue` 而不是无锁队列，因为状态频率低，Qt 事件循环已提供线程切换和对象生命周期保护。队列对相同设备的未处理快照进行覆盖合并，并设置容量上限，防止恶意或异常广播淹没 UI。

### 5. 权威来源和派生状态

- 在线：最近一次有效快照未超过其 TTL。
- 被控人数：目标快照 `host.sessions` 中有效唯一会话数量。
- 控制端名称：同一会话列表中的设备名和来源 IP。
- 脚本状态：目标本机进程和活动清单验证得到 `unknown`、`idle` 或 `running`。
- Busy：设备在线且被控会话数量大于零；Busy 在设备列表仍使用在线色，右侧人数徽标单独表达占用。
- 设备过期：状态变为 Offline，清空被控会话；脚本状态变为 Unknown，而不是 Idle。

控制端公布的 `controller.targets` 只用于关联、诊断以及确认本机存在待建立/已建立远控，不参与其它设备的人数统计。

### 6. 本地状态提供者

实时服务通过回调读取本地快照：

- 主机被控会话来自 `StreamRuntime::activeSessionCount()` 和控制端详情导出。
- 脚本状态复用 `DeviceStatusService` 的目标本机清单和进程校验逻辑。
- 本机控制目标由 `DeviceGrid` 在远控窗口建立、关闭和连接状态变化时发布。

远控原生层保留 ICE 断开立即取消会话和相同公钥重连替换旧会话的修复。实时服务检测到本地提供者的快照变化后立即广播；提供者读取在本机完成，不产生网络轮询。

### 7. 手动 TCP 校准保留，周期轮询停用

标题栏手动刷新继续调用 TCP 49101，对用户明确选择的刷新动作执行一次全设备校准。启动延迟刷新和设置页自动刷新定时器不再作为状态来源，自动刷新设置入口从 UI 移除或停用。

保留 TCP 服务有助于诊断广播被防火墙拦截的设备，但不会周期创建连接，也不承担实时性。

### 8. 跨广播域使用 UDP 订阅租约

定向广播不会经过路由器，因此控制端对不属于任一本机 IPv4 子网的已配置设备发送轻量 `subscribe` 数据报。订阅包含协议版本、控制端稳定设备 ID、启动 ID、实际来源 IP 和有界租约时间；目标端只保存有上限的订阅地址表，不把订阅者创建为设备条目，也不允许订阅报文携带控制命令。

- 控制端在设备列表建立或变化时立即订阅跨网段目标，并约每 10 秒续租一次。
- 目标端保存约 30 秒订阅租约；首次订阅或订阅者重启时立即回发当前完整状态。
- 后续状态变化、补发和自适应心跳除同网段广播外，同时向未过期订阅者单播同一完整快照。
- 状态接收仍要求快照公布 IP 与 UDP 来源 IP 一致，并且来源 IP 必须已存在于本机设备列表；订阅来源不修改 UI 状态，因此可以不是目标端设备列表成员。

选择订阅推送而不是把每台目标盲目单播给其设备列表，是因为控制工作站本身可能不在目标端的设备列表中。租约让目标端只向实际运行且主动关注它的跨网段控制端推送，同时在控制端异常退出后自动回收地址。

## Risks / Trade-offs

- [UDP 广播被防火墙拦截] → 启动日志记录绑定和发送结果，手动 TCP 刷新仍可诊断和校准。
- [多网卡、VPN 或虚拟网卡产生错误广播范围] → 只使用有效、已启用、非回环 IPv4 接口，并对每个接口使用计算出的定向广播地址。
- [UDP 丢包或乱序] → 使用完整快照、变化补发、心跳、`bootId` 和 `sequence`，不使用增量计数。
- [设备名称或 IP 被伪造] → 仅映射设备列表中的来源 IP，广播只影响显示；控制命令仍经过现有授权 TCP/SSH 路径。
- [脚本进程结束但活动清单未触发文件事件] → 活跃状态下每秒重新验证本机脚本进程，变化后立即广播。
- [大量无效广播淹没事件队列] → 限制数据报大小、协议版本、字段数量和队列容量，并按设备覆盖尚未处理的旧快照。
- [广播不能跨子网] → 同网段保留一次定向广播；跨网段控制端向已配置目标建立有界 UDP 订阅，目标后续按租约单播完整快照。
- [伪造订阅造成放大或内存增长] → 只接受私有 IPv4、来源 IP 与报文一致、字段有界的订阅，限制订阅者数量并用短租约自动清理；订阅只触发只读状态返回。

## Migration Plan

1. 引入实时状态数据结构、JSON 编解码和纯状态归并逻辑，不切换 UI。
2. 启用 UDP 49104 广播接收和自适应心跳，保持现有轮询用于对照。
3. 将 `DeviceGrid` 在线、人数、控制端名称和脚本 Logo 切换为实时服务信号。
4. 停止启动自动刷新和周期全设备轮询，保留手动刷新。
5. 统一更新局域网设备；旧版本不会出现在实时总线中，只能通过手动刷新看到瞬时状态。
6. 对跨网段设备启用 UDP 订阅续租；更新后的目标收到订阅后立即向控制端单播当前状态，随后由变化事件和心跳续租状态。

回滚时可停止实时服务并恢复 `DeviceGrid` 的启动和周期刷新调用；TCP 49101 协议未删除，因此回滚不需要恢复数据格式。
