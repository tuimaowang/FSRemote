## Why

设备在线状态、被控人数和远端脚本运行状态目前依赖按设备逐个 TCP 轮询，状态变化不能即时显示，并且异常退出或丢失结束事件时可能残留旧会话和旧图标。局域网内所有 FSRemote 节点本身同时具备控制端和被控端能力，适合通过统一的实时状态广播和本地消息归并机制降低延迟、减少连接开销并自动纠正丢包后的状态。

## What Changes

- 新增统一设备状态快照协议，每台设备广播自身在线身份、被控会话、脚本运行状态和正在控制的目标。
- 新增程序内状态消息队列和单一状态归并器，网络接收、ICE 会话、脚本运行和超时事件不再直接修改 UI 缓存。
- 状态变化时立即广播完整快照，并使用少量补发提高 UDP 变化事件到达率。
- 空闲设备使用低频心跳，存在远控或脚本任务时使用高频心跳；接收端通过 TTL 判定离线并清理派生状态。
- 同一广播域继续使用每网卡定向广播；位于其它已路由网段的已配置设备通过 UDP 订阅租约接收目标端定向推送，不恢复 TCP 状态轮询。
- 被控人数只以被控端公布的活动会话快照为准；控制端公布的目标租约仅用于关联、诊断和异常恢复，不参与人数相加。
- 脚本状态改为 `unknown`、`idle`、`running` 三态，设备离线时保持未知语义，不把无法确认误报为脚本结束。
- 使用稳定设备 ID、进程启动 ID、会话 ID 和单调序号处理设备重启、重复会话、乱序包和延迟包。
- 移除周期性的全设备状态轮询作为主要同步方式；保留用户手动刷新时的一次 TCP 查询用于显式校准和诊断。
- **BREAKING**：实时广播状态只在升级后的设备之间生效；旧版本设备不会参与新的实时状态总线。

## Capabilities

### New Capabilities

- `realtime-device-state-sync`: 定义局域网统一状态快照广播、消息归并、在线 TTL、被控会话人数、脚本运行状态、重复与乱序处理以及 UI 实时更新行为。

## Impact

- 新增系统层设备状态广播、接收、队列、归并和超时管理组件。
- 修改远控主机会话生命周期，使会话变化向统一状态服务发布快照。
- 修改脚本运行状态恢复和结束路径，使其向统一状态服务发布三态状态。
- 修改 `DeviceGrid`，由统一状态服务驱动设备在线、被控人数、控制端提示和脚本运行 Logo。
- 调整现有 `DeviceStatusService` 和自动刷新设置，使 TCP 查询转为手动校准入口。
- 需要选择固定 UDP 端口、处理多网卡定向广播并配置 Windows 防火墙兼容性。
- 需要处理 `192.168.1/2/3` 等互相可路由但广播域隔离的部署，控制端以低频订阅续租让目标端学习跨网段状态接收地址。
