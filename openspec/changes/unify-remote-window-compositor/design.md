## Context

当前远控窗口由 Qt 顶层 QWidget、D3D11 原生子 HWND、独立标题栏表面和性能浮层共同组成。窗口移动、尺寸循环、子窗口 WM_SIZE、SwapChain Present 和 DWM 合成分别发生在不同路径，导致代码事件成功并不代表最终屏幕表面连续。

重构需要保持 H265/D3D11 零拷贝路径和现有远程输入协议，同时把“谁拥有最终可见像素”收敛到一个明确的组件。窗口必须在普通呈现、交互缩放、最终收尾、设备丢失和软件回退之间有清晰状态边界。

## Goals / Non-Goals

**Goals:**

- 由一个统一合成器负责远控画面、黑边、标题栏、性能信息和状态遮罩的最终可见像素。
- 交互缩放期间保留最后有效画面或最新可用画面，不因父窗口、子 HWND 或默认擦除路径短暂清空内容。
- Qt 几何、原生窗口几何、D3D 输出区域和输入坐标保持一致。
- 保留 D3D11 零拷贝、BGRA 软件回退、多窗口、DPI、全屏、重连和远程输入行为。
- 提供可选的最终可见像素诊断，能够把实际空白帧与普通 resize 事件区分开。

**Non-Goals:**

- 不修改 WebRTC SDP、H265 编码器、码率策略或 Host 端协议。
- 不在本 change 中增加新的第三方渲染库；优先复用现有 Qt、Win32、D3D11 和 DWM 能力。
- 不保证在设备驱动本身失效时继续使用硬件表面；设备丢失仍可进入软件回退。

## Decisions

### 1. 单一顶层像素表面

统一合成器成为窗口的唯一可见渲染拥有者。远控纹理、标题栏、黑边、性能文本和遮罩在同一帧中提交，运行时不再依赖多个相互覆盖的可见 HWND。

备选方案是继续保留 D3D 子 HWND，仅增加更多擦除和 resize 保护；该方案无法消除 DWM 多表面提交竞态，因此不采用。

本次实现选择 Windows DirectComposition 作为统一顶层目标：D3D11 `CreateSwapChainForComposition` 创建的 SwapChain 挂到远控顶层 HWND 的根视觉树，交互缩放只更新视觉位置和最终缓冲尺寸。旧的子 HWND SwapChain 保留为运行时回退路径；DirectComposition 初始化失败时必须回到旧 Presenter，不能把会话直接推入黑屏。

### 2. 交互缩放采用稳定表面策略

进入交互缩放后，合成器锁定最后有效的源帧和渲染资源，使用统一输出变换适配实时窗口尺寸；不在每个像素尺寸事件中销毁并重建多个可见表面。松手后只执行一次最终尺寸资源调整，并立即补交缓存帧。

备选方案是每次 resize 都调用 `ResizeBuffers`，但这会放大 DWM 和 GPU 资源切换频率，不采用。

### 3. 明确的呈现状态机

合成器至少包含 `Idle`、`InteractiveResize`、`FinalizeResize`、`HardwareFallback` 和 `DeviceRecovery` 状态。状态转换必须统一处理表面可见性、缓存帧、输入区域和回退，禁止窗口类和 Presenter 各自隐藏/显示表面。

### 4. 统一输入和坐标映射

所有鼠标命中、标题栏按钮、远程输入和性能浮层区域都基于同一份窗口几何快照计算。渲染输出的内容矩形、DPI 缩放和输入反向映射不得各自重复推导。

### 5. 可见结果诊断优先于事件计数

保留事件/HRESULT 诊断，同时增加受控的窗口像素采样或截图探针，只在测试开关启用时运行。诊断需要记录采样时间、窗口区域、黑色像素比例、帧序号和合成状态，从而验证用户实际看到的空白帧。

## Risks / Trade-offs

- [GPU 合成迁移复杂] → 先以 feature flag 保留旧路径，按画面、标题栏、输入、回退四个阶段迁移。
- [软件回退视觉不一致] → 复用同一份布局快照和内容矩形，软件路径也由统一合成器作为唯一像素拥有者。
- [DPI/全屏行为变化] → 在每次 DPI、全屏和显示器切换时重建布局快照，并加入固定尺寸矩阵测试。
- [统一表面增加渲染工作] → 标题栏和性能文本只在状态/几何变化时更新缓存，远控视频帧仍使用 GPU 路径。
- [驱动差异] → 保留 BGRA 回退和设备恢复状态，诊断记录硬件能力与回退原因。

## Migration Plan

1. 新增合成器接口、布局快照和状态机，不改变旧窗口行为。
2. 在测试开关下让合成器接管远控内容表面，验证普通呈现和软件回退。
3. 将标题栏、黑边、性能信息和状态遮罩迁移到同一合成帧。
4. 迁移输入命中、拖拽、全屏、DPI 和多窗口生命周期。
5. 开启交互缩放稳定表面策略，运行像素采样诊断和回归测试。
6. 默认切换到新路径；旧路径保留一个版本周期作为回退，验证通过后删除。

回滚策略：feature flag 关闭后恢复旧 Presenter 和旧窗口协调路径，不改变 Viewer/Host 协议和持久化数据。

## Open Questions

- 统一表面采用 DirectComposition visual 作为顶层输出承载，D3D11 SwapChain 使用 `CreateSwapChainForComposition` 创建；旧的直接绑定子 HWND 路径仅作为回退。
- 像素采样诊断默认只保存统计信息，还是允许测试模式保存短时 PNG 序列？
- 旧标题栏和性能浮层文件的删除时点是否与新路径默认启用同一版本？
