## Context

本机页目前由 `DeviceGrid` 手绘一个资源卡片和一个系统信息卡片。`LocalSystemInfoService` 已能提供 CPU 型号、架构、逻辑处理器、物理内存总量、网络字段和全部本地盘符，并通过独立采样器每秒刷新 CPU、GPU、内存占用。新布局需要删除身份/网络信息、把硬件摘要放回对应资源行，并增加 Windows 内存模块、插槽以及 GPU 型号/显存查询。

## Goals / Non-Goals

**Goals:**

- 用一个白底卡片纵向展示 CPU、GPU、内存和磁盘。
- 保持现有 CPU/GPU/内存一秒采样和圆环缓动行为。
- 通过只读 Windows 接口补充 GPU 型号、专用显存和内存模块硬件信息。
- 在硬件接口缺失、超时或返回不完整数据时逐字段降级，不影响其它资源显示。
- 保持任意数量盘符的动态布局。

**Non-Goals:**

- 不显示电脑名称、Windows 版本、IPv4、MAC、子网掩码或网关。
- 不实现进程列表、温度、功耗、风扇、内存序列号、厂商、零件编号或通道模式。
- 不把静态硬件信息加入每秒采样，不写入配置或设备同步协议。

## Decisions

### 静态硬件信息继续由 LocalSystemInfoService 一次性读取

扩展 `LocalSystemInfo`，增加首选 GPU 摘要、内存模块列表和物理插槽总数。进入本机页或手动刷新时读取一次；每秒定时器仍只采集三个占用百分比。相比把 WMI/DXGI 查询放进定时器，这能避免隐藏的 COM 枚举和适配器枚举成为持续开销。

### GPU 摘要使用 DXGI 枚举

Windows 使用 DXGI 枚举硬件适配器，忽略软件适配器，优先选择专用显存最大的设备；只有集成显卡时仍使用可用硬件适配器。显示适配器描述和专用显存。实时 GPU 百分比继续沿用现有 GPU Engine 聚合口径，不尝试把最繁忙引擎反向映射到特定适配器。

替代方案是 WMI `Win32_VideoController`，但其显存字段在现代显卡上可能截断且刷新语义不稳定，因此选择已链接的 DXGI。

### 内存模块和插槽使用有界 WMI 查询

Windows 查询 `Win32_PhysicalMemory` 的容量、SMBIOS 类型、配置速率和定位字段，并查询 `Win32_PhysicalMemoryArray.MemoryDevices` 获得总插槽数。枚举使用有限等待时间，失败时保留已获得的模块或回退到仅显示内存总量。COM 已由其它组件初始化时接受当前 apartment，不重复撤销不属于本调用的初始化。

页面把容量相同的模块格式化为 `2 × 16 GB`；容量不同时显示 `16 GB + 8 GB`。类型或速率存在多个不同值时显示“混合”，未知值显示明确占位。总插槽未知时仅显示“已安装 N 条内存”。

### 单卡片采用固定资源行和动态磁盘行

卡片顶部依次使用 CPU、GPU、内存三行；左侧为标签，中间为圆环，右侧为硬件摘要。内存行增加高度容纳容量组合、插槽和类型/速率。磁盘区位于分隔线下方，每个盘符使用文件资源管理器式横向容量条和“已用 / 总量、可用”文本。卡片高度按实际磁盘数量增长，不重新引入第二张卡片。

### 字段按资源归属展示

CPU 行显示型号、逻辑处理器和架构；GPU 行显示型号和专用显存；内存行显示占用、已用/总量、模块组合、插槽、类型和速率。原系统信息卡中的身份、操作系统和网络字段完全不绘制，避免在新布局中形成隐形的第二信息区。

## Risks / Trade-offs

- [部分主板不公开插槽总数] → 仅显示已安装内存条数量，不伪造 `/ N`。
- [WMI 服务禁用或查询超时] → 返回部分或空模块信息，CPU/GPU/内存占用和磁盘继续显示。
- [多 GPU 机器的占用与型号不完全对应] → 型号明确作为首选硬件摘要，百分比保持“整机 GPU 最繁忙引擎”语义。
- [窄窗口下型号文字过长] → 使用省略号裁切，容量、数量和百分比等关键数字优先保留。
- [盘符过多导致卡片超出内容区] → 延续现有按盘符增长行为并压缩单行高度；本次不新增滚动容器。

## Migration Plan

无需数据迁移。发布后本机页直接采用新结构；回滚时恢复旧绘制函数和原 `LocalSystemInfo` 字段使用即可，硬件查询没有持久化副作用。
