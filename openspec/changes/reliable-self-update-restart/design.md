## Context

当前 `UpdateService` 直接在 FSRemote 运行期间将 UNC 共享目录中的 EXE、Qt/FFmpeg DLL 和插件覆盖到应用目录。Windows 对已加载映像的占用使该流程不可可靠完成，逐文件失败还会留下混合版本。项目已具备运行载荷白名单、语义版本文本和设置页入口，可在保留这些用户体验的前提下分离准备阶段与安装阶段。

## Goals / Non-Goals

**Goals:**

- 主程序运行期间只读取共享目录并准备完整的本地暂存载荷。
- 由无 Qt 依赖的独立更新器在主程序退出后替换文件。
- 更新失败时恢复旧安装，成功或回滚后自动重启 FSRemote。
- 更新器保持通用、稳定，不理解业务文件清单，也不访问共享目录。
- 正确比较语义版本，避免远端旧版本触发降级。

**Non-Goals:**

- 本阶段不建设 HTTP/CDN 更新服务、数字签名、灰度发布或强制升级后台。
- 本阶段不改变现有共享目录地址和设置页主要交互。
- 本阶段不自动提升管理员权限；安装目录不可写时明确失败并保留原安装。

## Decisions

### 独立原生更新器

新增 `FSRemoteUpdater.exe`，使用 Win32 API 和 C++ 标准库构建，并采用 MSVC 静态运行库，避免加载待替换的 Qt/MSVC 动态库。更新器只接受任务文件路径，等待 PID 退出、执行备份/替换/回滚和重启。

替代方案是批处理脚本或主程序自替换。脚本的转义、权限、错误恢复和进程等待较脆弱；主程序自替换无法解决已加载 DLL 占用，因此不采用。

### 从本地临时副本运行更新器

主程序把安装目录中的稳定更新器复制到 `%LOCALAPPDATA%/FSRemote/Updates/runner` 后启动。运行副本不占用安装目录中的更新器，因此未来发布包仍可替换安装目录内的更新器，而普通版本无需更新它。

### 简单版本化任务协议

主程序生成 UTF-8 JSON 任务，包含 `schemaVersion`、主进程 PID、暂存目录、安装目录、备份目录、重启程序、版本以及文件相对路径和大小。更新器仅接受 `schemaVersion=1`，路径必须是相对安全路径，拒绝 `..` 和绝对载荷路径。

### 准备与安装分离

主程序先把共享载荷复制到 `%LOCALAPPDATA%/FSRemote/Updates/<version>/payload`，验证必需文件和文件大小，最后写任务。暂存失败不会触碰安装目录。第一阶段使用大小校验；SHA-256 清单和版本目录原子发布作为后续增强，不阻塞解决当前文件占用问题。

### 目录级备份与事务状态

更新器按任务清单先将现有目标文件复制到独立备份目录，再将暂存文件复制到目标。任一步失败则用备份恢复已涉及文件；新增且原先不存在的文件会在回滚时删除。`FSRemote.version` 最后写入。

### 重启结果传递

成功后以 `--updated-from`、`--updated-to` 参数启动 FSRemote；回滚后以 `--update-rollback` 和错误状态启动旧程序。更新器日志写入本地更新目录，主程序启动后可向用户显示结果。

## Risks / Trade-offs

- [应用目录无写权限] → 准备阶段先探测可写性，更新器失败时不破坏原安装并写清晰日志；后续再增加 UAC 提权。
- [主程序关闭超时] → 更新器等待有限时间后放弃安装并重启/提示，不强杀进程。
- [发布过程中共享载荷变化] → 版本文件继续最后写；客户端全部复制成功后才启动更新。后续用版本目录和 SHA-256 清单完全解决并发发布窗口。
- [断电发生在替换中] → 备份目录和状态文件保留；本阶段优先保证同一执行中的自动回滚，后续补充启动恢复状态机。
- [更新器本身存在缺陷] → 保持协议和职责极小，并从临时副本运行，使未来可由旧副本安装新版更新器。

## Migration Plan

1. 构建并随主程序部署 `FSRemoteUpdater.exe`，旧客户端仍可按旧方式收到首次过渡版本。
2. 过渡版本开始使用暂存和独立更新器；后续版本不再直接覆盖运行中的安装。
3. 更新失败时保留旧版本文件、备份和日志，用户仍可启动原程序。
4. 验证稳定后再迁移共享目录到 `releases/<version>` 与哈希清单方案。

## Open Questions

- 若实际部署目录位于受保护的 `Program Files`，后续是否需要按需 UAC 提权。
- 是否在第二阶段加入 SHA-256 和版本独立发布目录。
