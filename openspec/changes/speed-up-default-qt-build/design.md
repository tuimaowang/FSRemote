## Context

根目录 CMake 当前有多个默认 `ON` 的测试分类开关，共创建二十余个测试可执行目标。Qt Creator 使用 `all` 作为普通构建目标时，所有未排除的测试目标都会参与编译；现有构建缓存中的分类开关已经是 `ON`，仅修改分类选项默认值无法立即改变旧构建目录。

## Goals / Non-Goals

**Goals:**

- 新配置和现有配置重新运行 CMake 后，普通 `all` 构建都不再自动编译测试程序。
- 测试源代码和分类开关继续保留，开发者可以明确开启并单独构建目标。
- 主程序、更新器和远控流生产库继续按原依赖构建。

**Non-Goals:**

- 不删除测试文件或历史测试产物。
- 不修改 Qt Creator Kit、生成器、并行任务数量或 Windows Defender 设置。
- 不自动清理现有 4.7GB 构建目录。

## Decisions

### 增加默认关闭的测试总开关

在顶层增加 `FSREMOTE_BUILD_TESTS=OFF`。每个测试分类块改为同时检查总开关与现有分类开关。旧构建缓存没有该总开关时，重新配置会采用 OFF，因此即使分类缓存仍为 ON，也不会继续创建测试目标。

### 测试目标使用 EXCLUDE_FROM_ALL

每个测试 `add_executable` 增加 `EXCLUDE_FROM_ALL`。这样即使用户开启总开关生成测试目标，普通 `all` 仍只构建生产目标；选择具体测试目标时，CMake 会正常编译其源码和依赖。相比要求用户每次在 Qt Creator 手动切换 `all`，该规则更稳定。

### 保留分类开关默认值

现有分类开关继续为 ON，总开关为唯一的日常门禁。需要完整测试环境时只需打开 `FSREMOTE_BUILD_TESTS`，所有既有分类会恢复；仍可单独关闭某一分类。

## Risks / Trade-offs

- [开发者误以为普通构建会同时验证测试] → 测试目标明确排除出 `all`，需要验证时单独构建并运行 CTest。
- [现有测试 EXE 仍留在构建目录] → 本变更只阻止后续默认构建，不删除已有产物，避免破坏用户文件。
- [CMake 配置首次重新生成仍需要时间] → 只发生一次；之后增量构建目标数量明显减少。

## Migration Plan

保存 CMakeLists 后让 Qt Creator 自动重新配置。无需清空构建目录；若需要测试，将 `FSREMOTE_BUILD_TESTS` 设置为 ON 并选择具体测试目标构建。回滚时删除总开关门禁及 `EXCLUDE_FROM_ALL` 即可。
