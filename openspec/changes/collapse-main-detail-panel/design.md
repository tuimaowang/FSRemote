## Context

主控窗口由无边框 `MainWindow` 和单个手绘 `DeviceGrid` 组成。当前 `m_leftSidebarCollapsed` 会隐藏左侧 240px 设备栏，并让右侧详情区向左扩展；窗口本身尺寸不会变化。新的交互要求保留设备栏、隐藏详情栏并同步缩窄顶层窗口，因此折叠状态、响应式尺寸、真实 Qt 子控件显隐、窗口边缘缩放和标题栏排版都需要一起调整。

## Goals / Non-Goals

**Goals:**

- 让 `<<` 收起详情栏而不是设备栏，设备选择、滚动、分组、拖拽和右键菜单继续可用。
- 收起时把主窗口固定为“240px 设备栏 + 42px 按钮窄条”的紧凑宽度，并在展开时恢复收起前的用户宽度。
- 折叠按钮始终位于设备栏右侧的独立区域，不覆盖设备行和设备滚动条。
- 收起状态只绘制紧凑标题、最小化和关闭按钮，展开状态恢复原有完整标题栏。
- 收起时隐藏所有详情页真实子控件，并暂停本机详情页资源采样；展开时按当前页面恢复控件和采样状态。

**Non-Goals:**

- 不持久化折叠状态或窗口宽度到配置文件。
- 不改变设备栏内部行高、图标、滚动、分组和设备操作语义。
- 不增加折叠动画，不改变主窗口高度，也不修改远控窗口。

## Decisions

### 使用独立的详情栏折叠状态

将 `m_leftSidebarCollapsed` 重命名为 `m_detailPanelCollapsed`。设备栏绘制和命中不再受折叠状态控制；折叠状态只负责右侧详情、标题栏完整内容和顶层窗口宽度。相比沿用旧变量反转大量条件，这样可以降低未来误把设备栏再次隐藏的风险。

### 紧凑窗口保留独立按钮窄条

紧凑宽度固定为 282px，其中设备栏保持 240px，右侧 42px 只放 `>>`。按钮继续靠近窗口底部，但 x 坐标始终位于 240px 设备栏之外，因此不会与设备、分组或滚动条重叠。展开状态的 `<<` 使用同一个窄条位置，详情页底部继续保留安全区。

### 只保存展开宽度并保持当前位置

收起前保存当前窗口宽度；收起后固定最小和最大宽度为 282px。展开时恢复至少 720px 的保存宽度，同时保持收起窗口当前的左上角和高度。相比保存整块几何，这样用户移动紧凑窗口后再展开不会跳回旧位置。

### 标题栏采用展开与紧凑两套可见集合

展开状态保持标题字标、版本、本机名/IP、更新、设置、刷新、最小化和关闭。紧凑状态隐藏本机身份、更新、设置和刷新，只绘制可截断的应用标题以及最小化、关闭；对应隐藏按钮也从悬停和点击命中中移除。这样无需压缩按钮热区，也不会让标题文字落到窗口控制按钮下面。

### 详情绘制与真实控件统一门禁

手绘详情区在 `m_detailPanelCollapsed` 时整体跳过。新增设备输入框、本机复制按钮、设置控件、脚本编辑器、日志控件和查找面板的可见条件统一增加 `!m_detailPanelCollapsed`。折叠后调用现有控件刷新入口，确保当前正在编辑的真实 QWidget 不会残留在紧凑窗口之外。

## Risks / Trade-offs

- [紧凑宽度下标题栏空间不足] → 使用紧凑标题集合，并对应用标题做省略显示。
- [收起后真实输入控件仍接收键盘或鼠标] → 所有详情控件显隐入口统一增加折叠门禁，切换时立即刷新。
- [展开后窗口宽度小于详情页最低可用宽度] → 保存宽度和恢复宽度均限制为至少 720px。
- [折叠时继续执行本机性能采样] → 页面可见性判断加入详情栏展开状态，折叠立即停止定时器并释放 CPU/GPU 查询句柄。
- [用户在紧凑状态尝试横向缩放] → 紧凑状态固定窗口宽度，只保留纵向缩放；展开后恢复普通最大宽度。

## Migration Plan

无需数据迁移。发布后旧按钮自动采用新语义；回滚只需恢复 `DeviceGrid` 的旧折叠状态和布局逻辑，不影响设备或设置数据。
