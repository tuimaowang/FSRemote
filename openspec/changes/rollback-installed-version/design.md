## Context

FSRemote 已使用共享目录 `更新资源/releases/<version>` 保存不可变发布载荷，并由主程序把目标载荷暂存到本机，再启动独立 `FSRemoteUpdater.exe` 等待主进程退出、事务替换文件和自动重启。当前 `UpdateService::applyRemoteUpdate` 只接受共享目录最新版本标记，并且只允许远端版本高于本地版本；常规设置页由 `DeviceGrid` 手绘卡片和少量真实 Qt 控件组合而成。

本变更需要跨越常规设置 UI、版本发现和更新任务准备，但不应复制更新器逻辑，也不能在主程序仍运行时直接覆盖安装目录。

## Goals / Non-Goals

**Goals:**

- 在常规设置页显示可回撤的历史语义版本，并允许用户明确选择目标版本。
- 仅允许回撤到低于当前安装版本、目录名合法且具备可验证运行载荷的不可变发布。
- 复用现有本地暂存、文件白名单、完整性校验、独立更新器、失败恢复和成功后重启流程。
- 在网络不可用、版本消失、载荷损坏、更新器缺失或任务启动失败时保持当前安装不变并给出错误。

**Non-Goals:**

- 不创建新的备份仓库，不保证已经从共享目录删除的版本仍可恢复。
- 不允许选择当前版本或更高版本作为“回撤”目标；升级仍走既有更新入口。
- 不改变远控协议、设备数据、端口、DLL API、发布版本递增和自动更新策略。

## Decisions

### 版本来源只使用不可变发布目录

`UpdateService` 枚举 `更新资源/releases` 的直接子目录，目录名必须能规范化为三段语义版本，规范化结果必须与目录名一致，并且严格低于本地版本。这样回撤选择与发布结构一致，不依赖可能已经指向更新版本的根版本标记。

备选方案是读取本地更新备份目录，但现有备份按单次任务组织，可能不完整且会被清理，不适合作为长期可选版本库。

### 发现阶段轻量筛选，执行阶段完整校验

下拉框刷新时检查版本文件和关键入口文件，排除明显未完成的发布；点击回撤后仍使用现有运行载荷白名单完整复制，并逐项校验暂存结果。版本目录可能在界面打开后被删除，因此执行阶段必须重新检查，不能信任下拉框缓存。

备选方案是在每次打开设置页时对网络共享做全量复制级校验，会阻塞 UI 且产生不必要的网络读取，因此不采用。

### 通用化现有更新任务准备流程

把 `applyRemoteUpdate` 的公共准备逻辑抽为接受显式目标版本的内部路径：升级入口继续要求目标版本高于本地，回撤入口要求目标版本低于本地。两者生成相同 schema v1 任务，由同一更新器执行事务替换并重启。

不新增任务 schema 字段，因为更新器完成“安装指定版本”的行为与版本高低无关；主程序只需在发起前执行方向约束。这样无需改变独立更新器协议。

### UI 使用真实下拉框配合手绘卡片

常规页新增一张与现有布局一致的卡片，真实 `QComboBox` 放在卡片右侧，并由 `updateSettingsControls` 统一处理可见性、滚动裁剪和启用状态。“回撤”按钮沿用手绘命中处理与消息框确认，避免引入额外布局体系。

下拉框按版本从新到旧排列；没有可用历史版本时显示占位项并禁用按钮。进入常规设置或共享版本状态变化时刷新列表。

## Risks / Trade-offs

- [网络共享枚举可能短暂阻塞 UI] → 只枚举一级目录并做少量关键文件检查，不扫描整棵载荷；执行时已有暂存流程负责完整校验。
- [历史版本可能与当前配置格式不兼容] → 回撤前显示明确确认提示；本变更只回撤程序运行文件，不主动删除用户配置和设备数据。
- [目标版本在选择后被发布端删除或损坏] → 点击时重新验证并在退出主程序前完成暂存；失败时不启动更新器、不退出当前程序。
- [回撤后的旧程序再次检测到新版本] → 保持既有更新策略，这是预期行为；用户仍可选择是否升级。
- [开发构建的本地版本文件缺失] → 复用现有安全默认版本规范化规则；没有严格更低的合法发布时不提供回撤。

## Migration Plan

1. 部署包含新 `UpdateService` 接口和常规页控件的版本，不需要修改共享目录结构。
2. 现有 `releases/<version>` 历史目录自动成为可选回撤目标；没有历史目录时界面显示无可用版本。
3. 如需撤销本功能，只需移除设置页入口和显式目标版本接口，既有更新器、发布目录和升级流程不受影响。

## Open Questions

无。目标版本保留时长由现有共享发布目录管理策略决定，不在本次代码中自动删除或保留版本。
