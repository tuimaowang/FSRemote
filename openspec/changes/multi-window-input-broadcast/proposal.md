## Why

同时远控多台设备时，用户目前必须逐个窗口重复执行相同的鼠标和键盘操作，批量部署、配置和演示效率较低。需要允许用户明确选择一个主控窗口，并把该窗口中的输入实时同步到其余远控窗口。

## What Changes

- 在每个非全屏远控窗口标题栏增加“键鼠同步”按钮，并清晰显示关闭、主控、跟随三种状态。
- 点击任一窗口的同步按钮后，该窗口成为唯一主控窗口；其远控画面内产生的键盘和鼠标输入照常发送给自身设备，并同步发送到其他所有符合条件的远控窗口。
- 点击跟随窗口的同步按钮时，主控权原子切换到该窗口；点击当前主控窗口的按钮时关闭整组同步。
- 新建立且连接正常的远控窗口自动加入当前同步组；跟随窗口关闭或断开只移除自身，主控窗口关闭、断开或进入不可输入状态时自动关闭整组同步。
- 以统一的语义输入事件广播，并针对每个目标映射绝对坐标和相对位移；正确处理按键/鼠标按钮释放、滚轮、自动重复和相对鼠标模式，避免目标设备残留按下状态。
- 只向连接正常且允许输入的其他窗口广播；单个目标发送失败不得影响主控窗口及其他目标，并把失效目标安全移出本次事件分发。
- 剪贴板同步、远控画质、远端更新、窗口拖动/缩放和其他标题栏操作不属于键鼠同步范围。

## Capabilities

### New Capabilities

- `multi-window-input-broadcast`: 定义远控窗口主控选择、标题栏状态、键鼠事件广播、坐标映射及安全释放行为。

### Modified Capabilities

无。

## Impact

- 主要影响 `src/ui/RemoteDesktopWindow.*` 的标题栏绘制、命中测试和输入发送路径。
- 需要新增由 `DeviceGrid` 持有、所有远控窗口共享的输入同步协调器，并接入普通/平铺窗口创建、销毁、连接状态与主控切换生命周期。
- 复用现有 `fsremote_stream_send_input` C API 和输入消息协议，不要求修改 Host 端协议或引入第三方依赖。
- 需要新增协调器单元测试，以及多窗口主控切换、坐标映射、断连和输入释放的集成测试。
